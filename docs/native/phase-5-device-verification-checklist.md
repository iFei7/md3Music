## A. T-P1-13 断网歌单播放（核心）

> 判定「已缓存」的方法：先**在线完整播放**该曲（至少 1 遍、含自然播完），再断网测试。

| # | 步骤 | 预期 | 实际 | 结论 |
|---|---|---|---|---|
| A1 | 在线播放歌单 [a, b, c]，完整播完 a、c（b 未播）；停在 a；**断网**（关 Wi-Fi + 移动数据）；点「下一首」 | 跳到 **c**（跳过未缓存的 b）并**继续播放**；进度条正常前进 | | ☐ |
| A2 | 承 A1，在 c 播放中点「下一首」 | 绕回/前进到**下一个已缓存曲**；若**无任何可播缓存** → 停止 | | ☐ |
| A3 | 歌单**全部未缓存**（用 0.6 的未播放歌单）；断网；点「下一首」 | **停止播放**；**队列与当前曲保留**（不消失）；UI 显示「网络不可用，歌单中无已缓存歌曲」 | | ☐ |
| A4 | 承 A3（已停播），**恢复网络**；静置 ≥5 分钟 | **不自动播放**；不自动重试；需**手动**点播放才出声 | | ☐ |
| A5 | 承 A3，恢复网络后**手动**点「下一首」或点某曲 | 正常走在线解析并播放（离线门不拦手动操作） | | ☐ |
| A6 | 断网；**当前曲已缓存**、正在播放；等它**自然播完** | 自动推进到下一个已缓存曲；无缓存则停止（同 A3 语义） | | ☐ |
| A7 | 断网；播放中**手动选一首未缓存的曲** | 按既有路径尝试解析并失败（**不**因离线而跳过用户显式选曲）；有明确错误提示，不静默 | | ☐ |
| A8 | 断网 + 循环模式 = **列表循环（ALL）**；队尾已缓存 → 绕回队首已缓存 | 正确绕回并播放 | | ☐ |
| A9 | 断网 + 循环模式 = **单曲循环（ONE）**；当前曲已缓存；等播完 | **重播当前曲**（不前进） | | ☐ |
| A10 | 断网 + 单曲队列（只有 1 首）且已缓存；等播完（ONE） | 重播；若未缓存 → 停止 | | ☐ |
| A11 | 断网；连续快速点「下一首」5 次 | 不崩溃、不卡死；最终停在一个已缓存曲或停止态；**无**无界重试日志 | | ☐ |
| A12 | 断网；观察 10 分钟 | **无**自动下载行为；流量统计为 0；无无限重试/无限等待 | | ☐ |

## B. T-P1-08 音频焦点运行时

> 设置入口：设置 → 播放 → 音频焦点中断处理（`KEEP_PLAYING` / `PAUSE_AND_RESUME` / `DUCK_AND_RESTORE`）+ 忽略音频焦点开关。

### B1. 三模式 × 中断类型

| # | 模式 | 中断方式 | 预期 | 实际 | 结论 |
|---|---|---|---|---|---|
| B1.1 | **保持播放** | 导航播报（短暂中断） | **不暂停**、**不降音量**；导航结束后仍正常播放 | | ☐ |
| B1.2 | **保持播放** | 来电（独占 LOSS） | **暂停**让路；挂断后**不自动恢复** | | ☐ |
| B1.3 | **暂停后恢复** | 导航播报 | **暂停**；导航结束后**自动恢复** | | ☐ |
| B1.4 | **暂停后恢复** | 来电 | 暂停；挂断后**自动恢复** | | ☐ |
| B1.5 | **降音量后恢复** | 导航播报 | 音量**降到约一半**（0.2 倍 duck 由 Media3 处理）；结束后**恢复原音量** | | ☐ |
| B1.6 | **降音量后恢复** | 其他 App 播放音乐 | 本端 duck 或被暂停（取决于系统）；恢复后音量正确 | | ☐ |
| B1.7 | 任意模式 | **忽略音频焦点 = 开** | 来电/导航**均不打断**；播放与音量完全保持 | | ☐ |

### B2. 关键验收项（务必逐条确认）

| # | 步骤 | 预期 | 实际 | 结论 |
|---|---|---|---|---|
| B2.1 | 播放中**用户主动暂停** → 触发一次短暂中断（导航）→ 中断结束 | **不自动播放**（必须保持暂停） | | ☐ |

| B2.4 | 播放中 → 中断暂停 → 中断期间**用户切歌** → 中断结束 | **不**把播放拉回旧曲；状态与用户操作一致 | | ☐ |
| B2.5 | 焦点中断发生时，观察日志与 UI | **不出现**「音源解析失败」类错误提示；`RecoveryOrchestrator` **不**消耗重试次数（无退避重试日志） | | ☐ |
| B2.6 | 播放中反复触发/释放焦点 10 次 | 无重复暂停、无音量跳变、无「切歌时音量突然变大」（若出现，记录 `[VolAudit]` 类日志） | | ☐ |
| B2.7 | 播放中**拔有线耳机** / **断开蓝牙** | 自动暂停；**恢复连接后不自动播放** | | ☐ |
| B2.8 | 播放中触发焦点抢占后检查媒体通知/锁屏 | 通知栏图标与播放态一致；无「双份暂停」 | | ☐ |

> 设置入口：设置 → 播放 → 记忆播放状态（默认开）。

| # | 步骤 | 预期 | 实际 | 结论 |

| C3 | 承 C1，点播放 | 从 ≈1:30 处继续（不从头） | | ☐ |
| C4 | 开启**随机播放**（打乱顺序）→ 杀进程 → 重开 → **关闭随机** | 恢复为**随机前的原始顺序**（不是随机序） | | ☐ |
| C5 | 循环模式设为 ALL → 杀进程 → 重开 | 循环模式仍为 ALL | | ☐ |
| C6 | 关闭「记忆播放状态」→ 杀进程 → 重开 | **不恢复**任何队列/进度；且历史持久化数据被清空 | | ☐ |
| C7 | 承 C1，检查 `adb shell run-as <pkg> cat shared_prefs/gracemusic_player_state.xml` | 含 `player_playlist` / `player_position` / `player_volume` / `player_state_data_version`；**不含** `http`/签名/token | | ☐ |

## G. 已知限制（测试前必读，避免误判为缺陷）

1. **`DUCK_AND_RESTORE` 模式下「用户中断期间主动暂停」仍可能被 Media3 内置恢复**（R5-14，上游行为，Dart 同）。若复现，记录为已知问题而非新缺陷。
2. **`abortCrossfade()` 未接入焦点路径**（R5-10）——交叉淡化（T-P1-07）**尚未落地**，故当前无淡化场景；若后续引入 T-P1-07，此项**必须**复测。
3. **缓存上限固定 512 MiB**（R5-01），设置项（F-CACHE-009）未接线；测试 A14 需临时改代码验证。
4. **恢复点仅接在 `MediaSessionService.onCreate`**（R5-22）——纯 UI 冷启动（从不触发播放域）不恢复，属预期。
5. **`Previous` 方向不做缓存过滤**（R5-05，产品已确认只做「前进」）。
6. **恢复位置未按曲目时长钳位**（R5-21）——若上次位置超出当前曲时长，恢复位置可能不精确。
7. **后台播放/焦点/Android 7–9 兼容性**在代码层**未验证**，本清单是唯一判据。
